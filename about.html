02. ABOUT

I work where performance testing meets live systems: model a workload, measure latency and throughput, then follow a slow path into the JVM or the platform when something breaks.

Most of the useful work is ordinary. Read the dump. Check the probe. Compare this run with the last one. Write down what actually moved the needle.

When the same diagnosis keeps returning, I prefer a small tool or a short guide over another long thread.

-- [ practice ] —

Evidence first. Least surprise in production. Shift performance left when a test can catch it.
